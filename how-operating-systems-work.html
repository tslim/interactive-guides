1 · A coordinator, not a desktop

The kernel guards the boundary.

HardwareCPU executes. RAM holds active data. Storage persists it.
KernelAllocates resources and checks privileged requests.
Wider OSIncludes services and tools. A desktop or shell is an interface.

“Administrator” is a user identity with permissions. “Kernel mode” is a CPU execution privilege. They are not the same thing.

2 · One program, many possible instances

Processes own resources. Threads take turns.

A process is a running program instance. Its threads share resources; the scheduler chooses which runnable thread gets CPU time.

RunningExecuting on a CPU.
ReadyWaiting for a CPU turn.
BlockedWaiting for an event, such as I/O.

Concurrency means making progress on multiple tasks. Parallelism means executing work simultaneously.

3 · Addresses are a view, not a location

Same address. Different bytes.

The CPU translates virtual addresses using OS-managed mappings. A virtual page maps to a RAM frame, with access permissions. Processes can also deliberately share a frame.

A page fault asks the OS to handle an access. It might allocate zero-filled memory, read backing storage, or reject the access—not necessarily crash or read a disk.

What about stacks, heaps, and malloc?

Stacks commonly hold call frames and local state; heaps support dynamically allocated objects. Both live in virtual address spaces. A runtime allocator can reuse memory it already manages, so every allocation does not require a system call or a fresh physical page. Copy-on-write can also make some write faults recoverable; the read-only example above deliberately has no such permission.

4 · When the working set does not fit

Keep a page, or read it again.

Clean file pagesCan be reclaimed and reloaded.
Dirty file pagesNeed writeback before changed bytes can be discarded.
Anonymous memoryMay move to swap, if configured.

If reclamation is insufficient, allocations can fail or a process may be terminated.

Virtual memory works even without swap. Swapping is one mechanism for managing pressure, not the definition of virtual memory.

5 · Names, objects, and bytes

A name is not a disk address.

Follow a file in a Unix-like, local filesystem. Directories resolve names; inodes hold file metadata; data blocks hold bytes. A block device knows addresses, not filenames.

Do applications look up the name for every read?

No. Opening a file normally returns a handle (a file descriptor in Unix-like APIs). Later reads and writes use that handle and an offset. Permissions, ownership, and access rules govern operations; a filename extension generally does not tell the kernel how to interpret the file’s contents.

6 · Software talks to hardware

Submit work. Wait for completion.

Drivers translate requests into device-specific work. Interrupts notify the OS of events. Many drivers run in the kernel; user-mode drivers exist too.

When I/O finishes, the task becomes ready. The scheduler still decides when it runs again.

7 · Visible is not necessarily durable

Written is not yet durable.

A buffered write can return after updating the OS’s page cache. Writeback and synchronization are later milestones. Compare an app crash with power loss.

Does journaling guarantee my latest edits survive?

Not by itself. Journaling can help recover consistent filesystem structures after a crash. Metadata journaling need not journal file contents. A structurally consistent filesystem can still have lost recent application data. Copy-on-write is another design approach; neither automatically makes every multi-file application operation atomic.

8 · A machine inside a machine

Who supplies the kernel?

A VM runs a guest kernel on virtual hardware managed by a hypervisor. An ordinary container isolates processes while sharing its hosting kernel.

Where do QEMU, KVM, and “type 1 / type 2” fit?

Type 1 and type 2 are conventional hypervisor categories, not complete architecture diagrams. KVM adds virtualization facilities to the Linux kernel; QEMU commonly supplies userspace machine/device models and uses KVM for hardware-assisted execution. QEMU can also emulate CPUs in software. A VM does not necessarily emulate every CPU instruction.

9 · The payoff

From launch to a durable save.

Follow one edit. Watch the active component, the process state, and each copy of the file.

The OS is not one mysterious operation. It is a collection of mechanisms for sharing resources, enforcing boundaries, and making useful work persist.

Keep the abstractions separate.

Program ≠ process. Virtual address ≠ RAM location. Filename ≠ storage block. Buffered write ≠ durable save. Virtual memory ≠ virtual machine.
