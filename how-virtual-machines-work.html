How processes, containers, and virtual machines isolate work

Ordinary arithmetic runs as application instructions on the CPU; it needs no system call. Virtual memory is an address-space abstraction, not a virtual machine.

Failure boundaries & model limits

App crash: this process stops. In the container example, the app is PID 1 in a private PID namespace: its exit also terminates any remaining processes in that namespace. The hosting kernel and other isolated workloads can continue, though shared services or application dependencies can still be affected.

Example views, not universal defaults: native/container views illustrate Linux-style PID and mount namespaces; the VM has a separate guest OS process list. PIDs and virtual hardware allocations are example configurations, not measurements or extra read events. A vCPU is scheduled on physical CPUs; virtual disk capacity need not be preallocated on the host. The container has a configured cgroup CPU/memory cap here. Native processes can also use namespaces and cgroups, and containers can be configured to share host namespaces. Visibility does not bypass access checks; resource caps do not appear automatically.

Hosting-kernel crash: native processes and ordinary containers sharing that kernel lose normal operation. Container isolation does not supply a separate kernel.

Guest-kernel crash: this guest and its applications stop. The host and other guests can continue under the intended isolation boundary. This is not a hypervisor crash: failure of the hypervisor or hosting infrastructure can affect multiple guests.

VM-backed container isolation also exists; desktop tools often host Linux containers inside a VM. “Shared hosting kernel” can therefore be a VM’s guest kernel. Isolation is a design boundary, not an absolute security guarantee.

Where do QEMU, KVM, and “type 1 / type 2” fit?

Type 1 and type 2 are conventional hypervisor categories, not complete architecture diagrams. KVM adds virtualization facilities to the Linux kernel; QEMU commonly supplies userspace machine/device models and uses KVM for hardware-assisted execution. QEMU can also emulate CPUs in software. A VM does not necessarily emulate every CPU instruction.
